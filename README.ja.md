# ⚡ Post Sync — ソーシャル投稿コレクター

オープンソースの Chrome 拡張機能です。**Facebook、Threads、X、Instagram、
LinkedIn** で残したい投稿を見つけたら、ワンクリックで**自分の Google Drive**
に保存し、Focus4ai ナレッジベースへの同期も選べます。

- **1 投稿 1 ドキュメント**。ファイル名は `日付_トピック_投稿者`、たとえば
  `20260813_会議前に聞きたいことを書き出す_王小明`
- **画像はドキュメントに埋め込み**。数日で 404 になる URL を保存するのではありません
- **先頭に固定リンク**。コメントを見にいつでも戻れます
- **同じ投稿を 2 回目に取り込むときは確認**し、以前の分へのリンクを渡します
- **最小権限**。`drive.file` スコープのみで、この拡張機能が作成したファイルしか
  触れません。Drive の他のものは見えません
- **インターフェースは English、繁體中文、日本語**。ブラウザの言語に従います

## 使い方

2 通りあり、どちらも自分で押すものです。

**右クリック**（推奨）。投稿を右クリックして**「⚡ この投稿を取り込む」**を
選びます。狙った投稿を曖昧さなく指定できます。コメントを右クリックしても、
そのコメントではなく投稿全体が取り込まれます。レイアウトや改修でフローティング
ボタンが出てこないときにも、この経路は残っています。

**フローティングボタン**。投稿までスクロールすると、右側に
**「⚡ この投稿を取り込む」**が現れ、その投稿に薄紫の枠が付くので、クリックで
どれが取り込まれるか分かります。

ショートカットキーは**既定では未設定**です。普段使っているキーと衝突しないよう
にするためです。必要なら `chrome://extensions/shortcuts` で Post Sync を見つけて
自分で割り当ててください。

**取り込みはすべて自分で押したものです。**自動収集は一切なく、ページを勝手に
スクロールすることもありません。それをすると「人が閲覧している」から「自動収集」
に変わり、アカウントのリスクがまるで違ってきます。

### 3 つの保存先、それぞれ独立

| | 何を保存するか | 誰のためか |
|---|---|---|
| **Google Drive** | 1 投稿 1 ドキュメント、画像は埋め込み | 人が読むため |
| **Focus4ai ナレッジベース** | Markdown、取り込み時に分割・索引化 | 検索のため |
| **persona-to-skill インポートファイル** | 自分でダウンロードする JSON 1 ファイル | 方法論の再構成のため |

どれかが失敗しても他には影響しません。Drive をつながずナレッジベースだけ使う
こともできます。

3 つ目が他の 2 つと違う点は、そのまま存在理由でもあります。**サーバー不要、
認証不要、どのブラウザでも同じ動作。** Drive の経路は `chrome.identity` を
使うため Chrome 専用です。Focus4ai の経路にはサイトと設定が必要です。
インポートファイルはダウンロードするファイルを 1 つ作るだけなので、Chrome
以外の利用者でも使えますし、Google には一切触れません。

## インストール

3 分です。開発環境も npm も不要です。

**手順 1：ファイルを入手する**（どちらでも可）

- **git を使わない場合**：このリポジトリ上部の緑の **`Code` → `Download ZIP`**
  を押します。展開後に必要なのは中の **`extension`** フォルダです。
- **git を使う場合**：

  ```bash
  git clone https://github.com/Joanna8521/PostSync.git
  ```

置いたままにできる場所（たとえば「書類」）に置いてください。
⚠️ インストール後に**削除・移動はできません**。拡張機能はそのフォルダから
直接実行されます。

**手順 2：Chrome に読み込む**

1. アドレスバーに `chrome://extensions` と入力し、**右上の「デベロッパー
   モード」をオン**にします。
2. 左上の**「パッケージ化されていない拡張機能を読み込む」**を押し、
   **`extension`** フォルダ（`manifest.json` が見える階層）を選んで「選択」を
   押します。
3. インストールすると設定ガイドが自動で開きます。**「Google に接続」**を押して
   自分のアカウントで承認してください。
4. facebook.com を開いて投稿までスクロールすると、右側に「⚡ この投稿を
   取り込む」が現れます。

> 承認画面で求められる権限は 1 つだけです。「このアプリが**作成した** Google
> Drive ファイルの表示、編集、作成、削除」。Drive の他のものは見えません。

### よくある問題

- **フォルダを選んだのに「マニフェストファイルがありません」と出る**
  階層が違います。`manifest.json` が入っている階層を選んでください。

- **押しても反応しない／フローティングボタンが出ない**
  そのタブに戻って `Cmd+R`（Windows は `F5`）で再読み込みしてください。
  拡張機能はページの再読み込み後に有効になります。それでも反応がなければ、
  拡張機能のアイコンをクリックして**「現在のタブを調べる」**を押してください。
  投稿が何件検出されたかをその場で教えてくれます。

- **Chrome を開き直すと「デベロッパーモードの拡張機能を無効にする」と出る**
  「キャンセル」で構いません。ストア以外から入れた拡張機能に対する Chrome の
  通常の確認です。

manifest には固定の `key`（公開鍵）が含まれているため、誰が読み込んでも拡張
機能の ID は同じになります。`mbckgmofgjkmfjofljddhgbhglfhjbom` です。1 つの
OAuth クライアントを共用できるのはこのためです。

## 言語

インターフェースはブラウザの言語に従います。設定は不要です。

| ブラウザの言語 | 表示 |
|---|---|
| 中国語（繁体字） | 繁體中文 |
| 日本語 | 日本語 |
| 英語 | English |
| それ以外 | English |

popup、設定ガイド、フローティングボタン、トースト、診断出力、エラーメッセージ、
Drive に書き込むドキュメント、ナレッジベースに書き込む Markdown のすべてが
対象です。

**閲覧するページの言語は別の軸です。** `adapters.js` と `naming.js` が照合して
いるのは Facebook が描画した文字、つまり操作バー、展開・折りたたみのラベル、
相対時刻です。これらは切り替えるのではなく、**すべての言語を同時に**認識する
必要があります。インターフェースを日本語にしている人が、中国語版の Facebook を
見ていることは十分にあり得るからです。2 つの軸を 1 つにまとめると抽出が壊れ
ます。インターフェースを日本語に切り替えた瞬間、中国語版 Facebook の
「讚 留言 分享」の行がまとめて本文に混入します。

インターフェースの文字列は `tools/messages.py` に 3 言語を並べて置き、
`tools/build_messages.py` がそこから 3 つの
`extension/_locales/*/messages.json` を生成します。3 つのファイルを手書きすれば
必ず食い違いが生じ、食い違った 1 行はある言語でキーそのものとして表示されます。
それはその言語でそのページを開いた人にしか見えません。`tools/run_tests.py` が
再生成して比較するので、`messages.json` を手で直しても静かには反映されません。

並べて置くことにはもう 1 つ利点があります。翻訳の出来は、3 言語を並べて初めて
判断できます。1 ファイルずつ読むと、どの行も正しく見えてしまいます。

## OAuth（自分のクライアントを使いたい場合のみ）

`manifest.json` には既に OAuth の client_id が入っているので、**インストール後に
「Google に接続」を押せばそのまま使えます**。設定するものはありません。Chrome
拡張機能の OAuth クライアントにシークレットはなく、client_id はそもそも公開
情報であり、オープンソースプロジェクトに書くのは標準的な方法です。

データの流れを最初から最後まで自分の GCP プロジェクトだけに通したい場合は、
自分で作って差し替えてください。

1. [Google Cloud Console](https://console.cloud.google.com/) でプロジェクトを
   作り、**Google Drive API** と **Google Docs API** を有効にします。

   ```bash
   gcloud projects create <プロジェクト ID> --name="Post Sync"
   gcloud services enable drive.googleapis.com docs.googleapis.com --project=<プロジェクト ID>
   ```

2. 「Google 認証プラットフォーム」→「始める」。Google は 2025 年に「OAuth 同意
   画面」をここへ移したので、古いチュートリアルとはメニューの位置が違います。
   <https://console.cloud.google.com/auth/overview>
   アプリ名は任意、対象は「外部」を選びます。

3. 「データアクセス」→ スコープ `.../auth/drive.file` を追加します。これは
   **機密ではない**スコープなので、Google の審査は不要で、テストユーザー 100 人
   の上限もありません。

4. 「対象」→**「アプリを公開」**。テスト中のままにすると、リストにある
   アカウントしか使えず、しかも**リフレッシュトークンが 7 日で失効**します。
   症状は「先週まで動いていたのに今日は失敗する」で、エラーメッセージは 7 日の
   ことを一言も言いません。

5. 「クライアント」→「クライアントを作成」→ アプリケーションの種類は
   **「Chrome 拡張機能」**、アイテム ID は
   `mbckgmofgjkmfjofljddhgbhglfhjbom`、取得した client ID を
   `extension/manifest.json` の `oauth2.client_id` に記入します。

> ⚠️ **同意画面にアプリのロゴをアップロードしないでください。**アップロードすると
> そのアプリは Google の**ブランド確認**のプロセスに入りますが、`drive.file` に
> それは本来まったく不要です。画像 1 枚のために数日から数週間待つのは割に
> 合いません。ストア掲載用のアイコンは別物で、こことは無関係です。

`manifest.json` の `key`（公開鍵）が拡張機能の ID を決め、Console に記入する
アイテム ID はそれと一致していなければなりません。一致しないと認証が通らず、
**しかもエラーメッセージは理由を教えてくれません**。`key` を変更したら次で
確認してください。

```bash
python3 -c "import json,base64,hashlib;d=base64.b64decode(json.load(open('extension/manifest.json'))['key']);print(''.join(chr(ord('a')+int(c,16)) for c in hashlib.sha256(d).hexdigest()[:32]))"
```

## 画像が実際にドキュメントに入るまで

`fbcdn` の画像 URL には期限付きトークンが付いているので、URL を保存することは
数日で 404 になるものを保存することです。ドキュメントが自分のコピーを持つ必要が
あり、そのために 2 段階あります。

1. **元の URL を Docs API の `insertInlineImage` に渡す。** Google が挿入時点で
   画像を取得してドキュメントに保存するため、元の URL が後で失効しても影響
   しません。これが速い経路です。
2. **拒否されたら自分でダウンロードする。** 拡張機能はこれらの画像 CDN の
   ホスト権限を持っているので、署名付き URL を扱えます。ダウンロードして Drive に
   アップロードし、数秒だけリンクアクセスを開いて Docs に取得させ、取得後ただちに
   アクセスを戻して一時ファイルを削除します。

画像は 1 枚ずつ処理するので、1 枚の失敗が他を巻き込みません。両方の経路が失敗した
ときだけ URL の貼り付けに戻り、そのときはドキュメント内に「これらの URL は通常
数日で失効します」と明記します。取り込めたふりはしません。

## Focus4ai 同期

popup で「Focus4ai ナレッジベースに同期」をオンにすると、取り込みのたびに Drive
への書き込みに加えて、Markdown をナレッジベースに書き込み、**その場で分割・
索引化**します（`PUT /api/doc` 経由。Focus4ai 側の変更は不要です）。

- **URL** にはサイトのルートを入れます（ホスティング版は
  `https://app.focus4ai.com`）。`focus4ai.com` は紹介サイトで API はないため、
  入力すると理由を説明して止めます。
- **フォルダ** は既定で `00_inbox/post-sync` です。
- **local_only** は既定で**オフ**です。ソーシャル投稿はほとんどが公開内容で、
  マークすると検索対象から外れてしまい、集めた意味がなくなります。非公開
  グループから集めるときにオンにしてください。（これは Mesh Sync とは逆です。
  あちらは自分の AI との会話を集めるので、顧客名や見積額が入っていることが
  よくあります。）
- サイトにログイン画面がある場合、拡張機能は同じブラウザのログインセッションを
  使うので、先にログインしてから同期してください。ログインページにリダイレクト
  されたときは明確にエラーを出し、成功したと偽ることはありません。

## persona-to-skill インポートファイル

[persona-to-skill](https://github.com/Joanna8521/persona-to-skill) は、ある人が
公開の場に残したものから、その背後にある方法論を、相談相手として使える形に
再構成します。**ソーシャルプラットフォームを自分で収集することはしません。**
理由は技術ではなく取得の可否です。X、Instagram、LinkedIn の robots.txt はそれを
禁じており、それを回避するツールは、それ自体が通報される理由になります。そこで
形だけを定義し、その形を作れるものなら何でも読み込めるようにしています。

Post Sync はちょうど、その文書が述べている経路そのものです。利用者が自分で押し、
自分の資格情報で動き、自動収集はありません。責任は操作する人の側に残り、それが
あるべき場所です。

popup で「persona-to-skill のインポートファイルを残す」をオンにすると、
**自分で取り込みを押した**投稿の本文がローカルにも残ります
（`chrome.storage.local`、既定で上限 500 件、満杯になると古いものから削除）。
「インポートファイルを書き出す」を押すと JSON が生成され、サーバーを経由せずに
ダウンロードフォルダに保存されます。

このスイッチは**既定でオフ**です。この拡張機能の姿勢は「取り込みはすべて自分で
押したもの」であり、その姿勢は裏で黙ってコンテンツを蓄積していては成り立ち
ません。

書き出したファイルには、2 つの項目を意図的に**記入しません**。

| 項目 | 記入しない理由 |
|---|---|
| `tier`（ソースの等級、T0 から T3） | 公開形態によって決まります。どの投稿が本人自身の言葉で、どれが広報担当や代筆によるものかは、機械には判別できません |
| `subject`（再構成の対象人物） | 誰を再構成したいかによって決まります |

既定値を推測して入れると、向こう側のゲートは**根拠があるように見える誤った値**を
受け取ります。それは値がないことより、はるかに危険です。値がなければ止められ
ますが、誤った値は止まりません。だからこの 2 つはインポート時の指定に委ね、
ファイル内の `note` にもそう書いてあります。

引用リポストに含まれる他人の言葉は `text` に混ぜず、`embedded_other_party` に
入ります。混ぜてしまうと、他人が言ったことが本人の方法論として抽出されます。

画像はインポートファイルに入らず、`image_count` だけが残ります。向こう側が
するのはテキストからの方法論の再構成であり、肖像に類するものの生成は明文で
拒否しています。

## CI

```yaml
tests                                    # ソース走査、5 つの多言語チェック、README チェック、142 のテスト、権限カバー率、パッケージ化
every gate rejects a broken input        # 6 つのゲートを意図的に壊し、すべて赤になることを要求
both pages render in all three languages # 実際のブラウザで両ページを 3 言語それぞれ描画
```

2 つ目のジョブには説明が必要です。その最初の版が**それ自体ゲートではなかった**
からです。

このジョブの仕事は、チェックが実際に止めることを証明することで、方法はひとつ
ずつ意図的に壊し、その壊しが実行を赤にすることを要求することです。最初の版は
`cp -r extension tools /tmp/snap_1` でスナップショットを取っていました。ソースが
2 つ、宛先が既存のディレクトリではないため、cp はそのまま失敗します。スナップ
ショットは一度も取られず、そして復元の手順が `rm -rf extension tools` を実行し、
何もないところからコピーし戻しました。

その時点以降、ツリーにはソースが 1 つも残っていませんでした。最初のチェック以降は
すべてファイルが消えていたために「赤」になり、ジョブはそれぞれを合格として数え、
**0 で終了**しました。機能しなくなったゲートを見つけることだけを目的とするジョブが、
そのひとつになっていたのです。

修正は 2 つです。復元を `git` 経由にしました。cp のように中途半端に成功することは
ありません。そして各チェックは、何かを壊す前に基準線が**緑である**ことを確認します。
赤い結果に意味があるのは、同じコマンドがその直前に緑だった場合だけです。最後に
ツリーが綺麗かどうかを確認します。編集が残っていれば復元が効いていないことを意味し、
それが最初の版が自身の失敗を隠した仕組みでした。

壊す側も 2 つ壊れていました。

| 壊す対象 | 最初の版の問題 |
|---|---|
| 字面の不可視文字を挿入 | `printf "\u200b"` は YAML、このシェル、`bash -c`、printf 自身のエスケープを通り抜ける必要があります。ローカルで 2 回実行したら結果が違いました。1 回は文字、1 回は 6 文字。現在は python がコードポイントから書きます |
| カタログにないキーを使う | `t('btnSave')` を変更していましたが、`btnSave` は `popup.html` の `data-i18n` 属性にしか現れず、`popup.js` は呼んでいません。sed は何にも一致せず、チェックは緑のままでした |

**確実に壊れない壊しは、チェックがないより悪いです。**

## プロジェクト構成

```
extension/
├── manifest.json        # MV3。固定の key（公開鍵）と oauth2 設定を含む
├── popup.html           # コレクション切替、接続状態、Focus4ai 設定、書き込み記録
├── onboarding.html      # インストール後に自動で開く設定ガイド
├── _locales/            # zh_TW / en / ja。tools/messages.py から生成
├── icons/
└── src/
    ├── i18n.js          # _locales の文字を HTML に入れる。innerHTML は一切使わない
    ├── adapters.js      # 各プラットフォームのアンカー（改修で触る唯一の場所）
    ├── naming.js        # ファイル名のトピック（service worker とテストで共用）
    ├── extract.js       # DOM からデータへ（純関数、テスト可能）
    ├── content.js       # フローティングボタン、全文展開、トースト
    ├── background.js    # OAuth、Drive、画像埋め込み、Focus4ai、重複排除
    ├── export_p2s.js    # persona-to-skill インポートファイルへ（純関数、テスト可能）
    ├── popup.js
    ├── onboarding.js
    └── toast.css
tests/
├── run.html             # 抽出層。ブラウザで開けば実行される
└── live.html            # フローティングボタン。偽のフィードと偽の chrome API で content.js を実際に動かす
tools/
├── messages.py          # 3 言語を並べたもの。これが正
├── build_messages.py    # _locales を生成。--check は書かずに比較する
├── jsstrings.py         # JS を 1 文字ずつ走り、文字列リテラルとコメントを分ける
├── run_tests.py         # ソース走査、多言語チェック、headless Chrome でテストページ
├── check_permissions.py # manifest の権限がコードの必要をどれだけ満たしているか
└── check_i18n_render.js # 2 ページを 3 言語で描画して確認（Playwright が必要）
```

- `key.pem`（リポジトリ直下、git には入れない）は .crx をパッケージ化するときに
  だけ必要な秘密鍵です。パッケージ化されていない読み込みには不要です。

## テスト

```bash
python3 tools/run_tests.py         # 全部緑でなければ通っていない
python3 tools/check_permissions.py # manifest の権限カバー率
```

`tests/*.html` をブラウザで開いて自分で見ることもできます。その場合は URL の
末尾に `?v=2` のようなパラメータを付けるのを忘れないでください。付けないと
ブラウザがキャッシュの古いファイルを出し、「直したのに反応しない」と見えます。

**`tests/run.html`** は抽出層です。ここで釘を打っているのは、**壊れても画面が
何も教えてくれない**類のことです。

- コメントが投稿として扱われる（Facebook では**コメント**が `role="article"` で、
  投稿は `div[aria-labelledby]`）
- フィード全体が「1 件の巨大な投稿」として扱われる
- Facebook のスクレイピング対策の難読化文字が本文、著者、ファイル名に入る
- 著者名に「認証済みアカウント」「フォロー」「共有範囲：公開」がくっつく
- コメントを右クリックして、投稿全体ではなくそのコメントが取り込まれる
- アバターがコンテンツ画像として扱われる
- 固定リンクにトラッキングパラメータが付き、同じ投稿のフィンガープリントが毎回
  変わって重複排除がまったく働かなくなる
- プラットフォームの改修で本文コンテナが空振りし、静かに空のものを取り込む
- 著者名や時刻がファイル名になり、フォルダ全体が同じに見える
- **Facebook が人によって違う DOM を返す**（A/B テストと段階的な配信）。使われて
  いることが分かっている投稿コンテナは 3 種類、`role="article"`、
  `div[aria-labelledby]`、`div[aria-posinset]` で、それぞれにフィクスチャが
  あります。このプラットフォームでは「自分の環境では動く」は他の人には一般化
  できません。
- 3 言語のインターフェース。`**太字**` のマークアップ描画と、HTML を含む
  メッセージがノードとして解析されず文字として表示されること
- ページ言語の照合表を中国語、英語、日本語で確認。加えて実際の本文 11 行が
  時刻と誤判定されないこと

**`tests/live.html`** はフローティングボタンです。偽のフィードと偽の `chrome`
API で `content.js` を実際に動かし、左下のパネルが報告します。content script が
注入されたか、投稿が何件検出されたか、ボタンの `display`、`z-index`、座標、
画面外に出ていないか。ボタンが出ないときはまずこのページを見てください。
問題がコードなのか環境なのかが分かります。

**`python3 tools/check_permissions.py`** は権限のカバー率です。`manifest.json` を
変更したら実行してください。

match pattern を間違えても**エラーは一切出ません**。Chrome は content script を
静かに注入しないか、background の fetch を静かに遮断するだけで、症状はまったく
別のもののように見えます（「このプラットフォームが反応しない」「画像が取れない」）。
そこでこのスクリプトは Chrome の照合規則を自分で実装し、実際の URL の形を
当てています。

- content script の matches が各プラットフォームの実際の URL の形を網羅して
  いるか（Facebook の `/photo/?fbid=`、Threads の新旧 2 つのドメイン、X と
  twitter.com など）
- host_permissions が 4 つの画像 CDN と 3 つの Google API を網羅しているか
- 逆に、**過剰に要求していないか**。宣言したのにどのコードも使わないものは、
  ストア審査を遅くするだけです

## 既知の制約

- **スマートフォンではフローティングボタンは出ません。** iOS も Android も
  Facebook アプリへの UI 注入を許可していません。モバイルは Safari Web
  Extension（可能ですが Xcode と開発者アカウントが必要）か、iOS ショートカット
  ＋ OCR になります。後者は Focus4ai が先に**トークン認証の**書き込み API を
  用意する必要があります。現在の書き込みはブラウザのセッション
  （`credentials: 'include'`）に依存しており、スマートフォンのショートカットに
  セッションはありません。
- **X の長い投稿は切り詰められることがあります。** X の「さらに表示」はリンクで、
  押すとページが遷移してしまうため、コードは押しません。ページから飛ばされる
  より、切り詰められた内容のほうがましです。
- **LinkedIn は固定リンクを DOM に置きません。** `data-id` / `data-urn` の
  activity urn から組み立てています。LinkedIn はレイアウトの変更も他より頻繁です
  （投稿コンテナは現在 `role="listitem"` で、旧版の `.feed-shared-update-v2` は
  もうありません）。
- **Instagram の投稿コンテナには意味的な属性が何もありません**（`role` なし、
  `data-testid` なし、class はすべて `.html-div`）。そのため固定リンク
  `a[href*="/p/"]` から上にたどり、`<time>` と `<img>` の両方を持つ最初の祖先を
  使います。見た目ではなく意味で探しています。
- **プラットフォームの改修で抽出がずれることがあります。** アンカーはすべて
  `src/adapters.js` にまとまっているので、直すのは 1 ファイルです。本文が取れない
  ときは画面上で明示し、静かに空のものを取り込むことはしません。
- **Chrome ウェブストアへの掲載には用途の説明が必要です。** facebook.com のような
  host permission を宣言すると、審査で「なぜ必要か」を問われます。その摩擦を
  減らすなら、`optional_host_permissions` ＋
  `chrome.scripting.registerContentScripts` による動的登録に変え、利用者が
  プラットフォームごとに自分で有効にする形にできます。

## プライバシー

- 取り込みは**すべて利用者の手動操作**（フローティングボタンまたはショートカット）
  で始まります。自動でアップロードされるものはありません。
- データは利用者自身の Google Drive と、利用者が指定した Focus4ai サイトにのみ
  書き込まれます。この拡張機能に独自のサーバーはありません。
- persona-to-skill インポートファイルは既定でオフで、オンにしても素材はローカルに
  留まります。ファイルにするかどうかは利用者が自分で押すことで、どの経路も
  それをどこかへ送りません。
- `drive.file` スコープのもとでは、拡張機能は自分が作成したフォルダとドキュメント
  しか見たり変更したりできません。
- 画像の 2 段目の経路では「リンクを知っている人が閲覧可」を一時的に開き、挿入が
  完了したらただちに戻して一時ファイルを削除します。
